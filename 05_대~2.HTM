> "주요화면 a,b,c안에서 b안은 별로이고 a와 c 중에서는 a가 좋다" — 팀원 1인
UI A/B/C안 전반에 대해 A 선호 / B 비선호 의견 1건. 발언에서 특정 화면이 지목되지 않아 적용 대상 화면은 다음 회의에서 확인이 필요합니다. 개인 의견이며 팀 최종 결정이 아닙니다.
※ v2에서는 이 의견을 HOME-01에만 귀속시켜 기록했으나, 근거가 불충분하여 문서 전반 의견으로 정정했습니다.
최종안이 확정되지 않았습니다. 각 안은 색상·버튼 위치가 아니라 정보구조와 사용 경험 자체가 다른 대안입니다. 이 문서는 팀 논의를 위한 후보이며 최종 디자인이 아닙니다. 화면 안의 약 이름·수치는 배치 확인용 임의 예시입니다. 맨 아래 "함께 결정해야 하는 것"의 연동 관계를 반드시 같이 보세요.

핵심 질문 — 보호자에게 전체를 요약할 것인가, 항목별로 나눌 것인가, 달라진 점을 먼저 보여줄 것인가.
전달 방식과의 관계 (v2.1 추가) — 전달 방식은 아직 [추가 결정 필요]입니다. (Decision Log B-20)
· 안 A 이메일 — REPORT-01 자체가 완결된 리포트 본문. 별도 웹페이지를 두지 않는다면 [자세히 보기]와 REPORT-02는 사용하지 않음(후순위).
· 안 B 보호자 대시보드 — REPORT-01 요약 → [자세히 보기] → REPORT-02 상세 구조 사용 가능.

세 안 공통 제약 — ① 대화 원문·음성·사생활 내용을 포함하지 않는다. ② 질환명·확률·진단·판정·의심 표현을 쓰지 않는다. ③ 대화 참여 횟수 감소를 상태 악화로 해석하지 않는다. 참여 횟수는 관찰된 사실로만 표기하며, 감정·인지 지표와 혼동하지 않는다. ④ 데이터 부족 시 추정하지 않고 "기록 모으는 중"으로 표시한다.

연동 관계

  1. 홈 A안 ↔ 복약 A안 — 홈에 오늘 일정을 노출하려면 시간대 프리셋 구조가 표현하기 쉽습니다.
  2. Blocker A(OCR 추출 범위) ↔ 복약 A안 — 약봉투 용법(1일 N회)을 추출하면 프리셋 초기 제안에 쓸 수 있습니다. 단 자동 확정이 아니라 사용자가 최종 선택합니다. [추가 결정 필요]
  3. 복약 A안 + B안 병행 — A안은 MED-01 설정, B안은 MED-06 기록 열람으로 역할을 나눠 둘 다 채택하는 방안도 가능합니다.
  4. 리포트 전달 안 A/B ↔ 리포트 A/B/C안 — 이메일이면 리포트 A안, 대시보드면 리포트 B안이 자연스럽습니다. [추가 결정 필요]
  5. CHAT-01 C안(배너) ↔ FT-06 — 배너 방식은 참여/거절 기록이 흐려져 "AI 대화 참여 정도"의 정확도가 떨어집니다.

공통 제약 — 어느 안을 고르든 유지

  1. DUR 관련 전 화면에 "의사·약사 상담을 권고합니다" 고정 노출. DUR-02에서 안전을 단정하는 표현 사용 금지
  2. 보호자에게 대화 원문·음성 미제공. 리포트 생성기 입력에 원문을 연결하지 않음 — 따라서 "원문 검출" 단계는 존재하지 않으며, 검수는 생성된 출력물을 대상으로 수행
  3. 분석·리포트 문구에 질환명·확률·진단·판정·의심 표현 금지
  4. AI 대화 참여는 선택. 거절 경로가 참여 경로보다 어렵지 않을 것
  5. 동의/미동의 선택지를 시각적으로 균등하게. 분석 동의를 강제로 유도하지 않을 것
  6. 복약관리에서 앱이 복용시간을 추천·처방하는 것처럼 표현하지 않을 것
